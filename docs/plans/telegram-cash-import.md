# План: импорт кэш-счёта из экспорта Telegram-канала

Статус: обсуждено с пользователем 2026-11-03; реализовано 2026-11-03, на проверке у пользователя.

## Goal

Траты и поступления наличными ведутся сообщениями в Telegram-канале. Их нужно загружать в кэш-счёт, проверяя всё перед импортом и не создавая дублей при повторной загрузке.

## Решения пользователя

- Нотация на будущее: `[+]сумма[ ]комментарий`. Число в начале — трата, с плюсом — поступление.
- Сообщения с любым вложением не учитываются совсем, даже с подписью.
- Если сообщение начинается не с числа, но число в нём одно, это сумма траты; с плюсом перед числом — поступления.
- Один канал соответствует одному счёту и одной валюте.
- Обязательный визард: перед импортом всё можно проверить и поправить.
- Название канала при первой загрузке берётся из файла и остаётся редактируемым. Если в новом файле другое название, визард спрашивает.
- То, что оставлено в «Проверить», сохраняется для разбора позже; при разборе можно проигнорировать.
- Часовой пояс уточняется при каждой загрузке, по умолчанию — выбранный в прошлый раз: время в файле зависит от того, где находился человек при выгрузке.
- Даты: пока поддержан один встреченный формат, остальные подстраиваются при появлении.

## Как устроено

- Карточка кэш-счёта → вкладка «Записи» → **«Импорт из Telegram…»**.
- Шаг 1: файл (можно несколько частей одной выгрузки), название канала, часовой пояс, статистика файла и прошлые загрузки с откатом.
- Шаг 2: вкладки «Проверить», «Траты», «Поступления», «Игнорировать», при необходимости «Изменились». В строке правятся дата, сумма, комментарий, категория и группа; сообщение можно разбить на несколько записей.
- Шаг 3: итог с суммами и балансом «было → стало», импорт одной кнопкой.
- Разбор и сортировка — в браузере (`src/lib/telegram-export.ts`), чистые функции с тестами на синтетике. Запись и память о решениях — на сервере (`server/src/telegram_import.rs`).

## Сортировка сообщений

Правила намеренно простые: первую загрузку пользователь отсматривает сам, дальше придерживается нотации. Догадок о банках, снятиях и валютах в парсере нет.

- Вложение или нет текста → сообщение не учитывается.
- Число в начале → сумма: трата, с плюсом — поступление.
- Иначе единственное число в тексте читается так же.
- Несколько чисел или сумма не только цифрами (`1.000`, `10 000`, `8к`, `7ка`) → «Проверить».
- Нет чисел → «Игнорировать».
- На проверке ничего не импортируется, но оставшееся сохраняется вместе с правками (`telegram_pending`): разобрать его можно позже без файла, в том числе кнопкой «Игнорировать». Если текст сообщения в новом файле изменился, оно разбирается заново.

## Дубли

- В HTML-экспорте нет ID канала, поэтому сообщение определяется парой **счёт + ID сообщения**, а название канала защищает от чужого файла: другое название — вопрос, канал другого счёта — запрет.
- Запоминаются все решения, не только импортированные: заметки и отклонённые сообщения не появляются снова (`telegram_messages`).
- Существующая проверка дублей импорта не подходит: она включает баланс, а у кэш-счёта он пересчитывается.
- Записи, внесённые вручную или через «Найти выводы в кэш»: та же сумма и направление в пределах ±2 суток → строка уходит на проверку с пометкой. Записи прошлых импортов не сравниваются: одинаковые покупки разными сообщениями — это разные покупки.
- Связи с банковскими списаниями визард не предлагает: так решил пользователь.
- Текст импортированного сообщения изменился: показывается на вкладке «Изменились», запись сама не меняется. Текст пропущенного сообщения изменился: сообщение разбирается заново.
- Удаление сообщений из канала экспорт не показывает.

## Откат

Загрузка хранится как `import_batches`. Откат удаляет её записи, снимает связи, если их поставили вручную, пересчитывает баланс и забывает решения: тот же файл предложит эти сообщения снова.

## Не делаем сейчас

- JSON-экспорт: в окне экспорта пользователя такого варианта нет.
- Другие форматы дат, начальный остаток счёта, распознавание фото.
