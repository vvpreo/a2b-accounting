# План: категории переводов между собственными счетами («<<--->>»)

## Goal

Две системные категории — доходная и расходная, обе называются `<<--->>` — по умолчанию отмечают переводы между собственными счетами. Каждая новая связь (перевод или вывод в кэш) сразу ставит их обеим сторонам; пользователь может переназначить на другую категорию.

## Решения (2026-10-29)

- Категории **системные**: `categories.system_key` (`transfer_income` / `transfer_expense`, миграция 025). Создаются приложением при запуске, после очистки данных и перед демо-сидом (`transfer_categories::ensure_system_categories`); описание — на языке приложения. Пользовательская корневая `<<--->>` того же вида «усыновляется», а не дублируется.
- **Нельзя удалить и перенести** под другую категорию (`category.system`); название, цвет и описание менять можно. На экране «Категории» и в выборе категории — всегда первыми.
- **Ставятся при новой связи** (`transaction_links::insert_link_unchecked` → `assign_on_link`): ручное связывание, применение предложения перевода / вывода в кэш, создание вывода в кэш, демо-сид. Только стороне без категории — категорию, поставленную пользователем, не трогаем. Сумма — вся сумма транзакции.
- **Уже связанные транзакции не трогаем** (решение пользователя: только для новых связей).
- **Разрыв связи снимает** `<<--->>`, если это единственная категория транзакции; переназначенная пользователем остаётся.
- **Вывод в кэш — тоже перевод**: обе стороны получают `<<--->>`.
- **Агент категорий их не видит**: ни в списке категорий промпта, ни в примерах, ни в отчёте «Примеры для агента».
- **Отчёт** не меняется: пара, у которой в выборке обе стороны, и так исключается из доходов/расходов; если видна одна сторона — она попадает в строку `<<--->>`, а не в «без категории».
