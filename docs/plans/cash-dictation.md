# План: записи кэш-счёта по описанию (агент)

Статус: обсуждено с пользователем 2026-10-30; реализовано 2026-10-30, на проверке у пользователя.

## Goal

Регулярные траты наличными (одна и та же сумма каждый месяц) не вводить по одной. Пользователь описывает текстом, какие записи нужны — в какие месяцы, какие суммы, какие категории, — агент готовит их, пользователь проверяет предпросмотр и создаёт записи одной кнопкой.

## Решения пользователя

- Ввод — **текст** (голос не нужен).
- Не шаблоны с автогенерацией, а «агент готовит импорт по моему описанию».
- **Предпросмотр** обязателен: правится каждая строка, создаётся только после подтверждения.
- **Строки считает приложение, а не модель**: модель описывает правила («5-го числа, янв–окт 2026, 25 000, категория X») и разовые записи, развёртывание в даты — детерминированный код.
- Только кэш-счета (на первом этапе).

## Как устроено

- Карточка кэш-счёта → вкладка «Записи» → кнопка **«Записи по описанию…»** рядом с «Добавить запись».
- Окно: поле описания → «Подготовить» → вызов модели (то же подключение, что у агента категорий, Настройки → ИИ).
- Модель получает: валюту и название счёта, сегодняшнюю дату, категории расходов и доходов (id: путь — описание, без системных `<<--->>`), последние записи этого счёта с категориями (чтобы «как в прошлом месяце» работало), описание жизни. Отвечает JSON:
  - `rules` — повторяющиеся: направление, сумма, категория, контрагент, комментарий, день месяца (1–31 или `last`), с какого и по какой месяц, шаг в месяцах;
  - `once` — разовые: дата, направление, сумма, категория, контрагент, комментарий;
  - `notes` — допущения и вопросы модели (показываются пользователю).
- Сервер проверяет ответ (одна повторная попытка при ошибке разбора), неизвестную категорию или категорию не того вида отбрасывает с пометкой, и **развёртывает** правила в строки: день > длины месяца → последний день месяца. Верхний предел — 1000 строк.
- Предпросмотр: сверху — текст описания, по которому подготовлен этот набор (пожелание пользователя), затем сводка (записей, приход, расход), заметки модели, таблица — галочка, дата, приход / расход, категория (выбор из дерева), контрагент, комментарий. Строка, у которой на счёте уже есть запись с той же датой, суммой и направлением, помечена «похоже на дубль» и по умолчанию снята. «← К описанию» возвращает к тексту (он сохраняется), чтобы уточнить и подготовить заново.
- «Создать N записей» — одна SQL-транзакция: кэш-транзакции (время 12:00 местное — чтобы граница суток в UTC не уводила запись в соседний месяц отчёта) + категория на всю сумму; баланс пересчитывается один раз.
- Журнал `agent_log`: вызов модели (`cash_dictation_call` — запрос, ответ, разобранный план, токены) и решение пользователя (`cash_dictation_created` — сколько строк создано из скольких предложенных, сколько исправлено).

## Не делаем сейчас

- Банковские счета, разбивка одной записи на несколько категорий, голосовой ввод.
