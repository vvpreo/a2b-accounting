# План: агент категорий на LLM (этап 2 предложений)

Продолжение [transaction-suggestions.md](transaction-suggestions.md): третье действие «Предложить категории».

## Goal

По кнопке для выделенных транзакций LLM предлагает **одну категорию** (любой узел дерева) с уверенностью 0–10 и обоснованием. Предложение появляется в колонке «Предложение», применяет его только пользователь. Агент подстраивается под манеру разметки конкретного пользователя через **примеры, которые пользователь отметил сам**, и через свой системный промпт. Каждый вызов модели и каждое решение пользователя пишутся в журнал, из него потом собираются evals для выбора модели.

## Что уже есть

- Таблица `transaction_suggestions` (kind `category` предусмотрен), колонка «Предложение», окно с обоснованием / рассуждениями / промптом, «Применить» / «Отклонить» / «Пересчитать».
- `SuggestionContext` без баланса (+ `slipNotes`, `lifeContexts`), эталонная выгрузка.
- `ai.rs`: один OpenAI-совместимый `chat_completion`, настройки в `app_settings.ai_provider_config`, ключ буквально или `env:VAR`. Пресеты: OpenRouter, OpenAI, Custom.

## Кого категоризуем

Как в этапе 1: пропускаем уже категоризованные, связанные (перевод / вывод в кэш) и с непросмотренным предложением связи. Только текст: картинки слипов модель не получает — всё нужное уже извлечено в `slipNotes`.

## Примеры (few-shot) — сбалансированы по категориям

Решение пользователя (2026-10-28): вся история не нужна — забьёт контекст; нужны **примеры по каждой категории**.

- Для каждой категории подходящего вида в запрос идут транзакции этой категории:
  - **все отмеченные пользователем ✨**, сколько бы их ни было (решение 2026-10-29: так пользователь «замораживает» сложные случаи по 5–7 примеров);
  - если отмеченных меньше N и включено «добирать автоматически» (по умолчанию да) — недавние размеченные, сначала с разными контрагентами.
- Плюс до 5 более ранних транзакций **с тем же контрагентом**, что у категоризуемой («Earlier transactions with the same counterparty»).
- Отметка — колонка **✨** на экране транзакций (между «Контекстом» и галочками выбора, скрываемая, заголовок — только ✨; решение 2026-10-29: ✨ — «агентский» значок, а не «избранное»; в ячейке категории отметки нет) и ✨ на вкладке «Категории → Примеры для агента»; массово — через «Действия ▾»; хранение — `category_examples (transaction_id)`; категория берётся живая из `transaction_categories`. Без категории отметить нельзя.
- Управление — вкладка **«Примеры для агента»** на экране «Категории» (см. ниже «Достаточно ли примеров»).
- Сама транзакция в свои примеры не попадает.

## Достаточно ли примеров (вкладка «Примеры для агента»)

Решение пользователя (2026-10-29): учить пользователя писать описания категорий — дело гиблое; агент должен учиться на разметке, а приложение — показывать, где примеров не хватает. Отмечать примеры — с «Транзакций» (✨ в ячейке, «Действия ▾»), разбираться — на вкладке «Категории → Примеры для агента».

Отчёт `category_examples_report` по каждой категории:

- **Размечено** — транзакций в категории и разных контрагентов среди них.
- **Агент видит** — сколько примеров из N уйдёт в промпт (✨ первыми, остальное — автодобор), раскрывается списком.
- **Агент: верно / ошибся** — текущее предложение агента (`transaction_suggestions`, `source = llm`) против категории, в которой транзакция сейчас. Считается по живым данным, а не по журналу: если пользователь потом перекатегоризировал, отчёт это учитывает.
- **Замечания:**
  - `no_examples` — ни одной размеченной (родитель, размеченный только через подкатегории, — не замечание);
  - `few_examples` — размечено меньше N;
  - `agent_misses` — агент предложил для транзакций этой категории другую, и ни одна из них не отмечена ✨;
  - `conflicts` — контрагент этой категории встречается и в других категориях того же вида (бар — «кафе» / «вредняхи»), и ни одна его транзакция здесь не отмечена ✨; разбиение одной транзакции на несколько категорий спором не считается;
- Замечание снимается действием, а не временем: отметили ✨ исправленную / характерную транзакцию — агент получает её как образец, замечание уходит. Это и есть «обучение» без дообучения модели.

## Промпт

- **Системный промпт в настройках агента** (редактируемый, с кнопкой «Сбросить к стандартному»): инструкции, как размечать — то, что пользователь хочет сказать модели своими словами.
- **Техническая часть добавляется приложением** и пользователем не редактируется, чтобы промптом нельзя было сломать разбор ответа: формат ответа (JSON `{categoryId, confidence, rationale}`), дерево категорий (id, путь, описание, только подходящего вида), примеры, контекст транзакции.
- Ответ валидируется: id есть в дереве и вид совпадает; иначе — одна повторная попытка с указанием ошибки, потом ошибка в журнал.

## Подключения и пресеты

Пользователь заводит **сколько угодно подключений** (`ai_connections`) из пресетов и выбирает одно для агента (`app_settings.agent.connection_id`). Пресеты — шаблоны, в поставке подключений нет; старая настройка `ai_provider_config` при запуске переносится в подключение.

| Пресет | Протокол | Ключ |
|---|---|---|
| OpenAI | OpenAI chat completions, `https://api.openai.com/v1` | свой токен |
| Anthropic | нативный Messages API (`/v1/messages`, `x-api-key`, `anthropic-version`) | свой токен |
| OpenRouter | OpenAI-совместимый | свой токен |
| Custom | OpenAI-совместимый или Anthropic, любой endpoint | по желанию |

Spark — это пользовательское подключение (Custom → `http://192.168.1.188:11434/v1`), заводится руками; на DEV-стенде заведено Cody. `ai.rs::chat` возвращает текст, рассуждения (`reasoning` / `reasoning_content` / `<think>` / блоки `thinking`), токены и точные JSON запроса/ответа (без ключа). Таймаут 300 с. Для облачных подключений в окне запуска и в настройках — предупреждение, что заметки уйдут провайдеру.

## Журнал (основа для evals)

Таблица `agent_log` — одна строка на событие:

- `llm_call` — пресет, base URL, модель, температура, полный обмен (`request` JSON — все сообщения как ушли; `response` — raw ответ), разобранный результат или ошибка, токены prompt / completion / reasoning / total, длительность, `transaction_id`, `suggestion_id`, `input_hash`, версия промпта (хэш системного промпта), id примеров, попавших в запрос.
- `suggestion_applied` / `suggestion_dismissed` — решение пользователя по предложению.
- `category_set_manually` — пользователь сам поставил категорию транзакции, у которой было (или отклонено) предложение агента: это и есть «правильный ответ» для evals.
- `example_marked` / `example_unmarked`.

Счётчик токенов — суммы по `agent_log` (по модели, по дню, всего) в настройках агента. «Выгрузить журнал» → JSON для построения evals.

## UI

- Настройки → «ИИ»: пресет, endpoint, модель, ключ, температура, «Проверить соединение» (как сейчас) + **системный промпт агента** + **токены** (сводка).
- «Действия ▾ → Предложить категории»: модалка с прогрессом (как у переводов / кэша), итог: предложено / пропущено с причинами / ошибки, суммарные токены.
- Колонка «Пример» (✨) в таблице транзакций, массово — «Отметить как примеры» / «Снять отметку».
- Окно предложения: категория, уверенность, обоснование, рассуждения, «что ушло в модель» — уже есть, добавляются модель, токены, время.

## Выбор модели (Spark)

Оценка на эталонной выгрузке (`samples/a2b-reference-set-2026-10-28-129.json`, 108 размеченных) скриптом в `.tmp/`: для каждой транзакции примеры — из остальных размеченных эталона, только более ранних по времени (честно, без подглядывания). Метрики: точное попадание, попадание в верхний уровень, калибровка уверенности, секунд на транзакцию, токены.

Кандидаты (все уже есть в пуле ollama на Spark, только текст):

## Этапы

1. Провайдеры: адаптеры OpenAI / Anthropic, пресеты, токены в ответе.
2. Журнал `agent_log` + сводка токенов + выгрузка журнала.
3. Примеры: `agent_examples`, колонка ✨, массовые действия, подбор K релевантных.
4. Действие «Предложить категории»: промпт, разбор, валидация, повтор, предложения `source = llm`, системный промпт в настройках.
5. Оценка моделей на Spark, выбор модели по умолчанию для пресета Spark.

## Оценка моделей (2026-10-28, Spark + Claude через ai-wrapper)

Эталон за октябрь, 108 размеченных; примеры — только из более ранних транзакций эталона (честно). Скрипт и сырые ответы — `.tmp/eval/` (не коммитится).

| Модель | Точно | Верх. уровень | «Подарок родителей» /38 | Остальные /70 | Точность при уверенности 8–10 | с/транз. |
|---|---|---|---|---|---|---|
| Claude Opus | 79% | 81% | 30 | 55 | 94% | 5,2 |
| Claude Sonnet | 70% | 72% | 23 | 53 | 87% | 3,8 |
| Claude Haiku | 70% | 77% | 24 | 52 | 76% | 13,5 |
| gpt-oss:120b (Spark) | 68% | 73% | 26 | 47 | 70% | 11,0 |
| qwen3.6:35b-a3b-q8_0 (Spark) | 67% | 71% | 21 | 51 | 67% | 4,8 |
| qwen3:30b-a3b-instruct-2507 (Spark) | 56% | 61% | 12 | 48 | 56% | 3,5 |
| gpt-oss:20b (Spark) | 56% | 62% | 18 | 42 | 57% | 9,9 |

- Локально лучше всех gpt-oss:120b, и только у него уверенность хоть что-то значит; qwen всегда ставят 8–10. qwen3.6 q8_0 трижды падал с «CUDA illegal memory access».
- Для Spark заведена производная модель `a2b-category-agent:gpt-oss-120b` (`num_ctx 16384`): по умолчанию ollama открывает контекст 262k, и 120b рискует не уложиться в кап 75g. С 16k — 64 ГБ.
- Формат ответа в примерах (`12: путь` → `category 12 (путь)`) на качество не повлиял; мягкий разбор оставлен — на DEV qwen3-30b однажды вставил путь прямо в JSON.
- Главные источники ошибок — не модель: один месяц примеров, пустые описания категорий, неоднозначная разметка (бар — «кафе» или «вредняхи»), и «подарок родителей», который решает контекст поездки, а модель не знает, кто её оплатил.

## Только очевидные случаи (2026-10-29)

Решение пользователя: агент предлагает категорию только при высокой уверенности, остальное оставляет человеку без предложения.

- В технической части промпта модели разрешено ответить `"categoryId": null`. «Очевидно» — когда решают собственные примеры владельца: тот же контрагент (или тот же вид покупки) в примерах в этой категории и больше нигде, и в транзакции нет ничего нового. `null` — новый контрагент, примеры расходятся, перевод человеку без говорящей заметки, покупка в контексте жизни (поездка, гости…), где примеры размечены иначе или их нет, заметка говорит, что куплено, но не для кого и кто платил.
- Порог в настройках агента: `agent.min_confidence`, по умолчанию 8. Ниже порога или `null` → вместо категории сохраняется метка «агент не уверен» (предложение `kind = category` без `category_id`, с причиной): в колонке «Предложение» серым курсивом, в окне — «Почему не уверен», применить нельзя, «Отклонить» убирает (решение пользователя 2026-10-29: видеть, где агент смотрел и не уверен, но без догадки). Исход `skipped / not_confident`; ответ целиком, включая догадку, в `agent_log` (`result.offered`, `result.minConfidence`). Метка не мешает спросить заново, когда меняется вход или порог.
- С тем же входом (`inputHash`) неуверенную транзакцию повторно не спрашиваем: новые примеры / заметки меняют вход. Галочка «Спросить заново» в окне запуска (теперь всегда видна) спрашивает и их.
- Все отмеченные ✨ примеры идут в промпт, сколько бы их ни было; N — минимум, до которого добирает автоподбор.

Оценка на эталоне (108 транзакций, те же честные примеры), «предложено → верно» при пороге:

| Модель / промпт | без порога | ≥ 8 | ≥ 9 |
|---|---|---|---|
| Sonnet, прежний промпт | 108 → 76 (70%) | 69 → 60 (86%) | 42 → 40 (95%) |
| Sonnet, v1 «очевидное» | 99 → 74 (74%) | 83 → 67 (80%) | 53 → 48 (90%) |
| **Sonnet, v2 (в коде)** | 95 → 77 (81%) | **59 → 56 (94%)** | 28 → 27 (96%) |
| Opus, прежний промпт | 108 → 85 (78%) | 66 → 62 (93%) | 41 → 41 (100%) |
| qwen3-30b (OpenRouter), v2 | 103 → 69 (66%) | 89 → 64 (71%) | 75 → 57 (76%) |

- v1 («заметка называет покупку — значит очевидно» + шкала «7–8 почти уверен») сделала модель смелее: в поездке за счёт родителей слип «лего» уверенно уходил в «Дети / Игрушки». v2 вернула прежнюю шкалу и требует, чтобы решали примеры.
- qwen3-30b почти не воздерживается и уверен всегда — для режима «только очевидное» не годится; Sonnet / Opus — да.

## Решения (2026-10-28)

- Примеры — сбалансированы по категориям (см. выше), ✨ + автодобор; раздел на экране «Категории».
- Системный промпт в настройках — только инструкции пользователя; техническая часть — приложения.
- Пресеты OpenAI / Anthropic / OpenRouter / Custom; любое число своих подключений; Spark — пользовательское подключение, в поставку не входит.
- Выкатка не ждёт оценки моделей; оценка — на эталоне за один размеченный месяц (заведомо не полностью репрезентативна), на Spark и через Claude (ai-wrapper).
- Следующий шаг (не сейчас): встроенные в приложение evals и подбор модели под категории пользователя.
